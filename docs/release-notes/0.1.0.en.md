# Gal World 0.1.0

English | [简体中文](0.1.0.zh.md)

This release reworks the play-quality path. The play page no longer scales the whole
canvas uniformly — it crops to the game's main window rectangle, so letterboxing no
longer fills the stage. Fullscreen recalculates from the iframe's own viewport instead
of being capped at the windowed scale. On the streaming side, the portal's per-message
limit now matches Selkies' 8 MB, so 1080p is no longer disconnected with `code 1009`.

Quality parameters are now editable per game.

## Highlights

- **Per-game quality settings:** CRF, paintover CRF, bitrate string, rate control mode
  (`crf` / `cbr`), and keyframe interval (seconds) are written to `game.env`. All are
  optional — leaving one empty means the portal does not manage that key, and any value
  written by hand in `game.env` is preserved
- **Crop to the game window:** the canvas is usually larger than the game window, and
  the remainder is black bars. The iframe is now scaled to the window and offset so the
  container's `overflow: hidden` crops the bars. A window that extends past the canvas is
  clipped to the visible area first, so no black gap is left in the bottom-right
- **Fullscreen fills the screen:** after entering fullscreen the crop is recomputed from
  the iframe's internal viewport, so the container scales up to fill the screen

## Improvements

- **Hovering the top edge no longer opens the game's window menu:** with the pointer on
  the topmost row, Kirikiri treats it as "moved to the window title area", pops its window
  menu and repaints once — experienced as the picture jittering when the mouse reaches the
  top. Hover movement in that band is now dropped on the input side; press and release are
  still forwarded, and no pixels are cropped
- **Window sampling spans the auto-enlarge window:** the enlargement in `run-game.sh` runs
  as a background loop, so the size may change 4–10 seconds after launch. Samples are taken
  at 1.5 / 4 / 8 / 12 seconds, and an early stop is only allowed past the 8-second mark, so
  the stale pre-enlargement rectangle is not used
- The top bar no longer covers the picture; a small gap at the top avoids accidental hits
  on the game window

## Fixes

- **1080p streaming getting stuck:** the portal's `StreamWsBridge` capped a single message
  at 1 MB, while one 1080p frame at CRF 8 with 4:4:4 is far larger. Selkies' frame was
  closed by the portal with `code 1009 Message Too Big`, which showed up as the stream
  freezing. The cap is now 8 MB, matching Selkies' `WS_MAX_MESSAGE_BYTES`
- **Intermittent 500 on the game list and home page:** after `findEndedSince` returned
  entities, the heartbeat thread could already have nulled `endedAt` on the same record
  (the old one is settled before a new one is opened), so the loop read `null` and threw
  `NullPointerException: temporal`. The batch statistics now skip concurrently closed
  records

## Upgrade notes

No database migration is required. The five new quality columns are added automatically by
`ddl-auto: update` and are all nullable, so an upgraded install works with defaults.

`minFromVersion` stays at `0.0.1`; there are no breaking changes, so older installs can
upgrade automatically.

Re-running the in-page "one-click deploy" is recommended so the new `run-game.sh`
(no title bar, enlargement threshold aligned with canvas calibration) and the streaming
parameters take effect. Swapping only the jar works too, but you miss the optimal window
enlargement and cropping.

## Known limits

- The Linux side has no GPU and uses llvmpipe software rendering plus x264 software
  encoding; at 1080p the game process takes about 684% CPU and selkies about 215% on a
  32-core machine. These numbers do not carry over to machines with a GPU
- Cropping depends on the window rectangle read via `xwininfo`. If the window moves or
  resizes after launch, the frontend re-reads it at four sample points; later changes
  require reopening the play page
