# Gal World 0.0.4

[English](0.0.4.en.md) | 简体中文

本版聚焦串流稳定性与画质。修掉了两个会让体验明显变差的问题：JDK 在线升级后门户
悄悄失去调用 `systemctl` 的能力（表现为启动进度条卡在 55%），以及画布自动校准
把分辨率越缩越小。

帧率不再被锁死。接入时可以写 `60,30-60`，Ctrl 快速跳过对话时游戏能跑到 60 fps；
码率控制模式也可按游戏选择 `crf` 或 `cbr`。

## 重点功能

- **帧率可配**：`FRAMERATE` 支持 `60,30-60` 三段式（初始值 + 范围），跳过对话时不再卡在 30 fps
- **码率控制可配**：`game.env` 写 `RATE_CONTROL_MODE=cbr` 可用 QP 上限压住快速跳过时的瞬时峰值，代价是复杂画面略糊
- **窗口自动放大**：游戏窗口不足画布一半时按画布放大，避免游玩页裁掉黑边后只剩小画面

## 改进

- **串流桥接有界队列**：门户 → 浏览器方向超预算时丢最旧的视频帧，让客户端自愈。此前队列无界，浏览器消化不过来时延迟会无限累积，表现为「越玩越卡、画面落后」
- 去掉首页假滚动条，滚动条样式统一走主题变量

## 修复

- **JDK 在线升级导致启动卡 55%**：`unattended-upgrades` 在门户运行中替换 JDK 后，所有 `fork()` 子进程失败，`systemctl` 调不到、会话状态恒为 `UNKNOWN`。新增漂移检测（退出让 systemd 重启）、前端 `UNKNOWN` 超时判失败、部署脚本写 apt 黑名单三层防护
- **画布自动校准越缩越差**：校准逻辑假设「画布 ≈ 窗口 + 24 最优」，读到小窗口就把画布缩小，窗口并不因此变大，结果画布从 1008×616 掉到 520×352、画质持续下降。现在窗口不足画布一半时保持大画布

## 升级说明

无需迁移数据库。建议重新执行一次 `deploy.sh` 或页面「一键部署」，让 apt 黑名单与新的
`run-game.sh` 生效。不重新部署也能正常运行，只是缺少 JDK 自动升级豁免与窗口自动放大。

升级过程只替换 jar，不动 `games/`、存档与 `wineprefix`。正在运行的游戏会话不受影响。

## 已知限制

- Linux 无 GPU 时使用软渲染与软编码，性能取决于主机 CPU。
- 浏览器串流要求反向代理支持 WebRTC / WebSocket upgrade。
- H2 是文件数据库，不要让多个 Portal 实例指向同一个数据目录。
- 用 wow64 Wine 跑 Kirikiri 自绘 UI 的汉化补丁时，游戏内按钮可能点击无响应，详见 `docs/WINE-RUNTIME-NOTES.md`。
