# Gal World 0.0.4

English | [简体中文](0.0.4.zh.md)

This release focuses on streaming stability and image quality. Two problems that made the experience noticeably worse are fixed: the portal silently losing the ability to call `systemctl` after an online JDK upgrade (which showed up as the launch progress bar stalling at 55%), and canvas auto-calibration shrinking the resolution further with each run.

Frame rate is no longer capped. You can set `60,30-60` when importing a game, so Ctrl fast-forwarding can run at 60 fps. Bitrate control mode is also selectable per game.

## Highlights

- **Configurable frame rate:** `FRAMERATE` accepts the `60,30-60` form (initial value + range), so fast-forwarding is no longer pinned at 30 fps
- **Configurable rate control:** setting `RATE_CONTROL_MODE=cbr` in `game.env` caps fast-forward spikes with a QP limit, at the cost of slightly softer detail on complex frames
- **Automatic window enlargement:** when the game window covers less than half the canvas, it is resized up to the canvas, so the play page does not crop down to a small picture

## Improvements

- **Bounded bridge queue:** when the portal → browser direction exceeds its budget, the oldest video frames are dropped so the client can self-heal. The queue was previously unbounded, so latency grew without limit when the browser could not keep up — experienced as "getting laggier over time, picture falling behind"
- Removed the fake scrollbar on the homepage; scrollbar styling now follows theme variables

## Fixes

- **Launch stuck at 55% after an online JDK upgrade:** once `unattended-upgrades` replaces the JDK under a running portal, every `fork()` subprocess fails, `systemctl` cannot be called, and session state is permanently `UNKNOWN`. Three layers of protection: a drift watchdog that exits so systemd restarts the portal, a frontend `UNKNOWN` timeout that fails with an actionable message, and an apt blacklist that prevents the auto-upgrade at the source
- **Canvas auto-calibration making quality worse:** the planner assumed "canvas ≈ window + 24 is optimal", so reading a small window shrank the canvas — the window never grew, and the canvas fell from 1008×616 to 520×352 with quality degrading each run. The canvas is now kept large when the window covers less than half of it

## Upgrade notes

No database migration is required. Re-running `deploy.sh` or the in-page "one-click deploy" is recommended so the apt blacklist and the new `run-game.sh` take effect. Running without redeploying also works; you just miss the JDK upgrade exemption and the automatic window enlargement.

The upgrade only replaces the jar; `games/`, saves and `wineprefix` are untouched. Running game sessions are not affected.

## Known limits

- Linux without a GPU uses software rendering and encoding; performance depends on host CPU.
- Browser streaming requires WebRTC/WebSocket upgrade support from reverse proxies.
- H2 is a file database; do not point multiple Portal instances at the same data directory.
- Running Kirikiri patched games under wow64 Wine can leave in-game buttons unresponsive to clicks; see `docs/WINE-RUNTIME-NOTES.md`.
