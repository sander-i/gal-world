# Gal World 0.1.0

[English](0.1.0.en.md) | 简体中文

本版重做游玩画质链路。播放页不再按整块画布等比缩放，而是按游戏主窗口矩形裁剪，
黑边不再占满 stage；全屏后按 iframe 内部视口重算，不再被窗口态的倍数封顶。
串流侧把门户的单帧上限对齐到 Selkies 的 8 MB，1080p 不再被 `code 1009` 断开。

画质参数进入游戏编辑页，每个游戏可以单独调。

## 重点功能

- **画质参数可在编辑页设置**：CRF、paintover CRF、码率串、码率控制模式（`crf` / `cbr`）、
  关键帧间隔（秒）写入 `game.env`。全部可空，留空表示门户不管理这个键，
  `game.env` 里人工写的值会被保留
- **按游戏窗口裁剪**：画布通常比游戏窗口大，多出来的是黑边；改为按窗口尺寸缩放
  再位移 iframe，外层 `overflow: hidden` 裁掉黑边。窗口越出画布时先裁到可见区，
  避免右下留黑缝
- **全屏不封顶**：全屏后按 iframe 内部视口重算裁剪，容器等比铺满屏幕

## 改进

- **顶部悬停不再弹游戏菜单**：指针停在画面最上沿会被 Kirikiri 当成「移到窗口顶部」，
  弹出窗口菜单、画面重绘一次，看起来就是「鼠标到顶部画面抖」。在输入侧拦掉这一段
  悬停移动，按下/抬起照常转发，画面本身一个像素都不裁
- **窗口采样跨过自动放大窗口期**：`run-game.sh` 的放大是后台循环，尺寸变化可能落在
  启动后 4–10 秒。采样点取 1.5 / 4 / 8 / 12 秒，跨过 8 秒才允许提前结束，
  避免拿到放大前的旧矩形
- 顶栏不再遮挡画面，画面顶部留空隙避免误触游戏窗口

## 修复

- **1080p 串流卡住**：门户 `StreamWsBridge` 的单帧上限是 1 MB，而 1080p + CRF 8 +
  4:4:4 的一帧远超 1 MB，Selkies 推过来就被门户以 `code 1009 Message Too Big` 断开。
  上限提到 8 MB，与 Selkies 的 `WS_MAX_MESSAGE_BYTES` 对齐
- **列表页与首页偶发 500**：`findEndedSince` 查出实体后，心跳线程可能已把同一条记录的
  `endedAt` 置空（开新记录前先结算旧的），遍历时读到 `null` 抛
  `NullPointerException: temporal`。批量统计改为跳过被并发关闭的记录

## 升级说明

无需迁移数据库。新增的 5 个画质参数列由 `ddl-auto: update` 自动添加，全部可空，
旧版本升级后按默认值工作。

`minFromVersion` 保持 `0.0.1`，本次没有破坏性变更，老安装可以自动升级。

建议重新执行一次页面「一键部署」，让新的 `run-game.sh`（去标题栏、放大阈值对齐
画布校准）与串流参数生效。只换 jar 也能跑，但拿不到窗口放大与裁剪的最优效果。

## 已知边界

- Linux 端无 GPU，走 llvmpipe 软渲染 + x264 软编码；1080p 下游戏进程约 684% CPU、
  selkies 约 215%（32 核机器）。性能结论不能套到有 GPU 的机器上
- 裁剪依赖 `xwininfo` 读到的窗口矩形。窗口在启动后移动或改变尺寸时，
  前端会在四个采样点重读；更晚的变化要重新进游玩页
